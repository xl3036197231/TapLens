## Realistic Deep Link walkthrough

Open `deep-link-demo.html` through a local HTTP server. The fictional "槐序 Campus" activity and message page offers seven original entry points and two supplemental Bilibili-claim/Taobao-product examples (`FIX-DL-008/009`). The original seven buttons lead only to a TapLens-style *expected static result* page. The two supplemental cards use their canonical `intent://` URI with the `taobao` scheme and `com.taobao.taobao` package as the main action, so a user tap in Android Chrome requests the installed Taobao app for the corresponding product. Each card also has a separate static preview; the preview's primary action uses the same Intent. The Intent includes a product webpage fallback if Chrome cannot launch the app. On this Android 15 emulator, Chrome first showed an Android activity picker. Selecting Taobao opened the Taobao detail Activity for `FIX-DL-008` (which displayed a network error) and the Taobao login Activity for `FIX-DL-009`. Product content remains unverified without a working network and Taobao session. No page launches an app or visits the product automatically, and the preview does not claim to have collected cloud evidence.

The preview shows the canonical URI, C's expected parse fields, risk hints and per-analysis `Lxx` IDs; users can copy the URI for a real C-device test. For FIX-DL-007 only, an explicit secondary link opens the existing local `short-link.html` so B can test the controlled web redirect separately. The logical `https://short.example.test/go/campus` remains a fictional fixture identifier and needs an exact test-environment mapping before B can collect real `Cxx`.

## Realistic QR walkthrough

`qr-demo.html` presents the 11 original `shared/datasets/qr/manifest.json` cases plus two supplemental paired QR codes (`QR12/13`). Each card shows its fixed QR PNG. The new PNGs encode the direct HTTPS URLs for the two Taobao products. The TapLens preview button shows an *expected static* result; a distinct “ordinary scan effect” link opens the actual product webpage only when clicked. An ordinary phone scanner can also read the QR and offer to open that URL. TapLens should continue to preview before navigation. Neither preview nor QR display follows a link automatically or collects `Lxx/Cxx` evidence.

Unlike the Day 2 site-only server, this walkthrough must be served from the repository root so the page can read the shared manifest and PNGs:

```powershell
python -m http.server 8767 --bind 127.0.0.1
```

Open `http://127.0.0.1:8767/mobile/test/ai/day2_site/qr-demo.html`. The static `QR01` URL is a `.test` fixture; live cloud testing needs B's current controlled URL and a temporary QR generated by `build_qr_samples.py generate-live`, as explained in `shared/datasets/qr/README.md`. Do not commit that temporary URL or code. Run `python -m unittest discover -s mobile/test/ai -p test_qr_demo.py` to check the demo's manifest and action boundaries.

QR12/13 encode HTTPS product URLs; FIX-DL-008/009 use Android Intent URIs with the `taobao` scheme for those same products, explicitly declare the Taobao package, and include the same HTTPS URL as a Chrome fallback. The fictional cards claim a Bilibili video. The product IDs came from a manufacturer's public product pages. Taobao may require login or a session check even when its app receives the Intent; reaching the product detail is a separate device check. The site has no affiliation to either brand.

Chooser boundary on this Android 15 emulator: Chrome itself launched `android.intent.action.PICK_ACTIVITY` after a user tap on both the `intent://` link and the HTTPS product link. An `intent://` probe with an explicit component and one without a fallback also showed the picker. Temporarily enabling Taobao's `item.taobao.com` user selection did not remove Chrome's picker; that setting was restored afterward. By contrast, a native `ACTION_VIEW` Intent with `setPackage("com.taobao.taobao")` (tested through `adb shell am start -p com.taobao.taobao`) opened Taobao's detail Activity directly. A static web page cannot force that native call or suppress Chrome's picker on this device. A no-chooser scenario needs a separate native app entry point or a device/browser where the target App Link resolves directly; it must be recorded as a different test condition.

The short-link case uses only `example.test` language and test-only values. The
form action is relative and must be blocked by the sandbox; no form submission
should leave the local test service.

All visual assets are local SVG fixtures under `assets/`; no external images,
fonts, analytics, or third-party branding are loaded. The prominent training
fixture notice is intentionally retained on the login page.

The login form uses a local `onsubmit` handler that prevents transmission and
navigates to `community-hub.html` only to demonstrate the post-login redirect.

B can serve this directory with any local static server and map the entry paths
to the URLs listed in `day2-scenarios.json`.
