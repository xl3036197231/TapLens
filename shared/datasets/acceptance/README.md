# D 成员 30 例验收矩阵

此目录把已有的安全样例与 AI 守卫用例整理成 **30 条可逐例记录的验收项**，基线固定为 `0cf68192d0a23db7fdf8b039d24a203ca869c3af`。它是测试定义；没有填写实测结果的条目不能计入通过数。

- D30-01～11：11 个仓库内 QR PNG 和安全预览；
- D30-12～21：7 个构造 Deep Link 与 3 个独立评测输入，仅静态解析；
- D30-22～29：8 个 AI 请求、报告守卫、回退或 Mock HTTP 用例；
- D30-30：Android 原生尝试记录落盘及异常退出恢复，当前为阻塞门禁。

`matrix.json` 只引用现有样例路径和编号，不复制二维码载荷、凭据或完整报告。每条包含执行方式、预期结果和必须保存的证据。`run_level=device` 需要在同一固定 APK 的实体设备上记录结果；`automated` 应保存实际命令与完整输出。历史测试日志不能替代本轮执行。

## 校验矩阵

在完整仓库根目录运行：

```bash
python3 mobile/test/ai/validate_acceptance_matrix.py --check-files
```

该命令核对 30 个唯一连续编号、分类数量、必要字段、来源文件及样例编号／测试标记。只检查矩阵结构时，省略 `--check-files`。**校验矩阵通过不表示 30 个产品用例通过。**

## 执行和记录

1. 固定 `main` 提交、APK SHA-256、设备型号和 Android 版本；自动化测试也记录 Flutter/Python 版本。
2. 对每个 `case_id` 记录 `PASS`、`FAIL` 或 `BLOCKED`，以及执行时间、实际输出、证据路径和失败原因。未执行保持 `NOT_RUN`。
3. QR、Intent、Wi-Fi、短信等载荷只安全预览；不唤起外部 APP、不连网、不发送短信。云端用例仅使用已批准的受控目标和任务。
4. D30-30 必须在 A 修正原生存储后，由独立设备测试证明“写盘失败不发 POST、异常退出重启只 GET”。Dart MethodChannel Mock 不能代替这一项。
5. 在 `submission/` 中汇总通过数、失败数、阻塞数及原始证据，再计算 README 的解析成功率、动作识别率、证据绑定率和耗时；各指标须写明分母和测量方法。

当前逐项状态和缺失证据见 [Day 9 D 测试报告](../../../submission/day9/test-report.md)。旧候选 C04 PNG 和手机完整真实 AI 报告缺失，不能从这 30 条测试定义推断为已通过。
