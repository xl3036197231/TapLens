# A 对 B 后端首版接口的审核记录

审核对象：`origin/feat/b-backend-bootstrap`

审核结论：**提交修改建议，暂不建议把云端证据契约标记为 `FROZEN-v1`。**

## 已确认的优点

- 登录、健康检查、额度和云端扫描任务分开，Flutter 容易按页面接入。
- 创建任务使用 `202`，状态区分 `queued`、`running`、`succeeded`、`failed`、`expired`，适合轮询。
- 错误响应有统一对象，方便 APP 显示“请重试”“额度不足”等提示。
- B 没有把 DeepSeek Key、原始海报图片或完整报告放进任务请求，符合隐私边界。
- 云端证据已有跳转、请求、表单、页面、截图和 `Cxx` 编号，能够支撑 A 的基础结果页。

## 合并前必须补清楚的地方

1. **截图怎么拿**：文档提到临时 URL，但没有具体 endpoint、认证头、过期时间和失败响应。请确定是带 Bearer 的截图接口还是短时签名 URL，并写出请求和过期规则。
2. **额度字段统一**：`/quota` 使用 `remaining`，创建任务响应使用 `quota_remaining`。建议统一为 `remaining`，或者明确二者分别表示什么。
3. **轮询契约完整**：补齐 queued、running、succeeded、failed 的完整 JSON 示例，写明建议轮询间隔、最大等待时间、`Retry-After`，以及每个状态的 cloud evidence 是 `null`、部分还是完整对象。
4. **扣额度时机**：写清楚请求校验失败、云任务超时、服务端异常时是否扣额度，避免 APP 显示与实际余额不一致。
5. **任务元数据**：说明 `task_metadata` 是否可选，是否应该并入任务结果；也要说明用户离线或轮询中断后如何恢复查询。
6. **注册后的登录态**：注册接口当前只返回 user，没有说明是否同时返回 JWT。需要明确“注册后自动登录”还是“注册成功后必须再调用登录”。

## 对 A 的影响

上述问题解决后，A 才能稳定实现额度页、任务进度页、截图查看和失败重试。当前可以先用 B 的 example 开发页面，但不能把这些字段当作最终冻结版。
