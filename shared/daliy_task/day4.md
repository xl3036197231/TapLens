## 二、第四天共同目标

用一条新生成的分析完成以下流程，并留下可复查的证据：

1. C 在手机上静态解析用户确认的短链接，返回本次分析的 `Lxx`。这一步不打开浏览器或其他 APP，也不访问网络。
2. 用户明确选择云端分析后，A 通过当次可用的 B 后端地址登录、查看额度、创建任务并轮询同一个 `task_id`。
3. B 的沙箱只访问 D 提供的受控测试站，返回 `C01-C04`；不会提交表单，不记录输入值。
4. A 展示同一 `analysis_id` 的本地和云端证据；D 确认报告只引用本次可用的 `Lxx/Cxx`，结论没有超出证据范围。
5. AI 真实调用不是本日主线。没有用户自愿提供的 Key 时，用规则报告和明确标注的离线 Mock 完成演示；失败时规则报告仍可见。

### 通过标准

- Android 模拟器实际走过“登录 → 额度 → 创建任务 → 轮询 → 报告”，不是只用命令行或旧 fixture 代替。
- 本次任务的 `analysis_id` 在 A、B、C、D 的记录中一致；任务 ID 和证据编号对应得上。
- 报告可展开查看证据来源；仅有本地链接结构时显示“证据不足”，不能称为安全。
- 截图与日志不含密码、访问令牌、真实个人信息或 API Key；B 的云端证据不含表单输入值。
- 汇总 Flutter、Android/Kotlin、后端和报告契约的实际检查结果；未跑的项目写“未验证”，不推测通过。
