# A 第三天模拟器演示与启动说明

> 负责人：A  
> 目标：在 Android 模拟器上演示一次本地预检、云端分析和报告展示。  
> 本文不记录某次运行的局域网地址、账号密码或任何 API Key；每次联调由 B 单独提供运行信息。

## 一、开始前向队友拿到什么

从 B 处拿到：

- 本次可访问的后端基础地址，例如 http://10.0.2.2:8000/api/v1；如果后端不在模拟器宿主机上，以 B 给出的地址为准；
- 测试账号的注册或登录方式；
- D 的短链接主案例；
- 后端和 worker 已启动的确认。

从 C 处拿到：

- 五类 analyzeLocalEvidence 输入和返回记录；
- 当前模拟器上使用的 APK 版本或提交号。

## 二、在 Windows 上构建并打开 APP

在 TapLens 仓库根目录打开 PowerShell：

~~~powershell
cd mobile
flutter pub get
flutter build apk --debug
adb devices
adb install -r build\app\outputs\flutter-apk\app-debug.apk
adb shell monkey -p com.taplens.app 1
~~~

如果模拟器列表为空，先在 Android Studio Device Manager 启动 TapLens_API35，然后重新执行 adb devices。

APK 默认输出位置：

~~~text
mobile/build/app/outputs/flutter-apk/app-debug.apk
~~~

## 三、连接 B 的云端服务

APP 的云端分析页默认把 Android 模拟器宿主机映射为 10.0.2.2，但要以 B 本次实际启动环境提供的地址为准。

1. 从首页选择“粘贴链接”。
2. 粘贴 D 提供的虚构校园短链接，点“开始本地预检”。
3. 确认页面展示本地解析字段和 Lxx，并显示“未启动外部应用，未访问网络”。
4. 点“提交云端深度分析”。
5. 在“后端地址”中填写 B 给出的地址；输入 B 提供的测试账号和密码。
6. 点“开始云端分析”，等待任务完成。
7. 若 20 秒后任务仍在排队或运行，点“继续查询”。这个按钮查询原任务，不会再创建任务。
8. 任务成功后点“打开报告页面”，核对风险、建议和 Cxx 证据。

如果出现连接错误，先确认 B 的服务仍在运行、地址从模拟器可访问、账号有效。不要连续点击“开始云端分析”来处理仍在运行的任务。

## 四、演示顺序

1. **本地预检**：展示短链接的 Scheme、域名、参数和 Lxx；说明解析只读取链接结构，不会打开应用或访问网页。
2. **云端采集**：展示 B 的任务状态从排队/执行变为成功，并展示报告中的 C01-C04。
3. **报告阅读**：先读一句话结论，再对照宣传承诺、实际行为和证据编号。
4. **AI 深度研判**：只有在演示者准备好自己的 DeepSeek Key 并确认一次调用可能消耗额度时才进行。Key 只保存在手机安全存储，不交给 B 后端。
5. **AI 不可用时**：保留规则报告并说明当前观察到的证据。不要为了演示而把真实 Key 写进文档、命令行或仓库。

## 五、目前不能由 A 单独完成的现场项

- 没有 B 当次地址、测试账号和运行中的 worker，就只能用APP 自带的固定高风险报告演示页，不能声称手机到后端真实链路已通过。
- 没有 C 的五类 MethodChannel 返回记录，就只能展示已有本地样例，不能声称五类输入都完成模拟器验收。
- 没有真实 AI Key 时，不执行真实 DeepSeek 请求；AI 用量和报告结果不能写成已实测。
