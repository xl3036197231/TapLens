# TapLens 第二天工作安排

> 日期：2026-09-22  
> 适用成员：A（Flutter）、B（后端）、C（Android 本地安全）、D（AI 与报告）  
> 工作方式：不按固定时间安排，按依赖顺序推进。  
> 第二天主线：短链接进入仿冒校园登录页。

## 一、第二天共同目标

完成一次真实 Android 联调：

> 手机输入固定短链接 → C 在手机本地解析 → A 展示本地风险 → B 执行云端分析 → D 生成高风险报告 → AI 失败时仍能显示规则报告

第二天只保证以下输入：

- 普通 `https://` 链接；
- `intent://` 或自定义 Scheme Deep Link。

二维码扫描、OCR、相册导入和多功能二维码先继续使用固定样本，不作为第二天主线。

后端联调采用手机和开发电脑连接同一 Wi-Fi、手机访问电脑局域网地址的方式。这只是开发阶段的联调方式，最终用户使用 APP 不需要连接开发电脑。

## 三、第二天统一顺序

1. 所有人从最新 `main` 拉取代码并创建自己的第二天功能分支。

## 六、C：Android 原生能力与真机验证

### 需要接着完成第一天的内容

1. 准备 Android SDK 或 Android Studio 环境。
2. 编译 `com.taplens.app` Debug APK。
3. 安装到真实 Android 手机。
4. 验证 Flutter 能调用 MethodChannel。

### 第二天新增内容

使用以下固定输入测试：

- `https://` 短链接；
- 自定义 Scheme；
- `intent://` Deep Link；
- 非法链接；
- 缺少协议的字符串。

确认输出包含：

- Scheme；
- 域名；
- 目标包名；
- 参数；
- fallback 地址；
- 风险提示；
- `Lxx` 证据编号。

同时确认：

- 不会自动打开外部 APP；
- 不会自动访问网页；
- 解析失败有明确错误信息；
- 输出符合 `local-evidence.schema.json`。

### C 的交付物

- 可安装的 Debug APK；
- 真机测试结果；
- MethodChannel 实际调用记录；
- 普通 URL、Scheme、`intent://` 三类结果；
- 错误输入示例。

### C 被 Android 环境卡住时先做什么

- 继续完善 Kotlin 单元测试；
- 增加固定输入和输出 fixture；
- 提供模拟 MethodChannel；
- 让 A 先使用模拟本地结果完成页面。

## 七、D：AI、报告校验与失败回退

### 第二天任务

1. 让报告模型严格对应正式 `analysis-report` Schema。
2. 自动检查报告中的 `Lxx/Cxx` 是否真实存在。
3. 实现一份 Mock AI 返回结果。
4. 实现真实 AI Client。
5. 用户在手机端填写自己的 API Key。
6. Key 只保存在手机安全存储中。
7. 手机只向 AI 发送脱敏后的证据。
8. B 的后端不接收、不保存用户 Key。
9. AI 返回内容必须通过 JSON 校验。
10. AI 失败时自动切换到规则报告。
11. 测试 Key 无效、余额不足、超时、限流和非法 JSON。

### D 的交付物

- AI Client；
- Mock AI；
- 报告 JSON 校验器；
- `Lxx/Cxx` 引用检查器；
- AI 失败回退规则；
- 短链接仿冒登录页高风险报告。

### D 被真实 AI 卡住时先做什么

- 先使用 Mock AI；
- 先完成证据编号校验；
- 先完成规则报告；
- 先完成脱敏逻辑；
- 真实 API Key 和网络恢复后再做真实调用。

## 八、依赖关系

| 未完成成员 | 会卡住谁 | 卡住内容 |
|---|---|---|
| A 正式报告接入未完成 | D、最终演示 | D 无法确认报告在手机上能正常展示 |
| B 后端地址或接口不稳定 | A | A 只能使用 fixture，无法完成真实云端联调 |
| C MethodChannel 未打通 | A | A 无法在手机上获得真实本地解析结果 |
| C 真机编译未完成 | 全员最终演示 | 无法证明 APP 在 Android 手机上运行 |
| D 报告校验未完成 | A | A 无法确认 AI 结论引用了真实证据 |
| D 真实 AI 暂时失败 | 只影响 AI 演示 | A、B、C 可以用 Mock AI 或规则报告继续 |
| A 页面暂时未完成 | 最终演示 | B、C、D 仍可继续各自测试 |

## 九、谁被卡住时先做谁的任务

- **A 等 C**：先用模拟 MethodChannel 接入页面。
- **A 等 B**：先用 HTTP fixture 完成登录、额度和结果页。
- **A 等 D**：先完成正式报告模型和静态页面。
- **B 等部署环境**：先跑测试、完善 fixture 和接口说明。
- **C 等 Android SDK**：先做 Kotlin 单元测试和本地证据 fixture。
- **D 等真实 API Key**：先做 Mock AI、JSON 校验、证据引用检查和规则回退。
- **任何人等待别人时**：先完成自己模块中不依赖外部输入的部分，并把等待内容标记为 `BLOCKED`。
