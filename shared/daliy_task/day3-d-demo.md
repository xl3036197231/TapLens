## 给普通用户的一句话

- 高风险短链：**“这条链接跳到了要求填写学号和密码的页面，请先核实来源，不要直接输入真实账号。”** 依据本次 B 快照 `C01/C02`，页面标题和截图可查 `C03/C04`。
- 本地证据不足：**“手机只读懂了链接地址，还没有看过页面，暂时不能说它安全。”** 依据 C `case03` 的 `L01`；格式错误的 `case05/06` 没有 `Lxx`，只显示解析错误。
- 包名不一致：**“链接指定的应用与预期测试应用不同，先别打开。”** 依据 D 样例的预期 `L02`；现场须以 C 当次生成的 `Lxx` 为准。
- 低风险示例：**“这个演示样例的页面与报名说明基本吻合，但提交前仍要核对域名。”** 旧 `low-risk.json` 引用 `L01/C01`，目前缺少同一次分析的真实安全页快照，不能把它当作 Day 3 实测结论。
- AI 回退：**“AI 暂时没有给出可信结论，原先发现的跳转和敏感表单风险仍然有效。”** 保留规则报告中的 `C01–C04`。

## 一页讲解词

1. 在模拟器输入 B 当次提供的受控短链接。先看本地预检：C 只解析协议、目标和参数，立刻给出 `Lxx`，此时没有打开其他 App，也没有访问网页。若本地只发现链接结构，页面应明确写“证据不足”。
2. 用户确认后启动云端任务。B 的沙箱观察到 HTTP 跳转 `C01`、登录表单的字段名 `C02`、页面摘要 `C03` 和截图 `C04`。沙箱不提交密码；页面自称的官方身份也尚未独立核实。
3. 展示 D 的高风险报告：短链接从普通校园服务入口进入要求学号和密码的页面。点开报告差异与证据编号，让观众看到每句话的来源。不要把其他分析中的同名 `L01/C01` 混用。
4. 可选展示 Mock AI：有效模型 JSON 通过 Schema、分析 ID 和证据守卫；换成不存在的 `C99` 会被拒绝；超时或非法 JSON 时页面继续保留规则高风险报告。没有用户自己的 Key 时不调用真实 DeepSeek。
